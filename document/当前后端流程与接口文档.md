# FRESH 后端系统流程与接口说明

## 1. 文档说明

本文档描述当前 `backend` 仓库已经实现的后端流程与 HTTP 接口，用于前后端联调、测试验收和后续维护。本文档只覆盖后端 API、后端流程、配置和数据约定，不描述前端页面实现。

当前系统角色：

| 角色 | 枚举值 | 说明 |
| --- | --- | --- |
| 新生 | `FRESHMAN` | 注册后默认角色，可报名、查看自己分组、提交任务 |
| 负责人 | `LEADER` | 可管理自己负责的分组、任务、公告、资料、审核和导出 |
| 管理员 | `ADMIN` | 拥有管理端全局能力 |

当前关键状态枚举：

| 类型 | 枚举值 |
| --- | --- |
| 用户状态 | `ACTIVE`, `DISABLED` |
| 报名状态 | `SUBMITTED`, `GROUPED`, `REJECTED`, `WITHDRAWN` |
| 时期类型 | `REGISTRATION`, `SELECTION`, `INTERVIEW`, `NOT_OPEN`, `FINISHED` |
| 年级 | `YEAR_1`, `YEAR_2`, `YEAR_3`, `YEAR_4`, `GRADUATED` |
| 验证码场景 | `REGISTER`, `RESET_PASSWORD` |
| 任务提交状态 | `PENDING`, `SUBMITTED`, `REVIEWED` |
| 公告范围 | `GLOBAL`, `GROUP` |
| 文件用途 | `TASK_ATTACHMENT`, `TASK_SUBMISSION_ATTACHMENT`, `MATERIAL_ATTACHMENT` |
| 通知类型 | `APPLICATION_REJECTED`, `APPLICATION_GROUPED`, `APPLICATION_UNASSIGNED`, `TASK_PUBLISHED`, `TASK_RETURNED`, `TASK_REVIEWED`, `ANNOUNCEMENT_PUBLISHED`, `MATERIAL_PUBLISHED` |
| 审计模块 | `AUTH`, `APPLICATION`, `GROUP`, `TASK`, `ANNOUNCEMENT`, `MATERIAL`, `CONFIG`, `EXPORT`, `FILE`, `NOTIFICATION` |
| 审计级别 | `NORMAL`, `IMPORTANT`, `MAJOR` |

## 2. 通用约定

### 2.1 基础路径与认证方式

后端 API 统一使用 `/api/v1` 前缀。除明确标注匿名可访问的接口外，所有 `/api/**` 接口都需要登录。

登录态使用 HttpOnly Cookie：

- 登录 Cookie：`lab_recruit_token`
- CSRF Cookie：`XSRF-TOKEN`
- CSRF Header：`X-CSRF-TOKEN`

所有已登录的非安全方法请求，例如 `POST`、`PUT`、`PATCH`、`DELETE`，都需要提交 CSRF Header。Header 值应等于前端从 `XSRF-TOKEN` Cookie 读取到的值。

### 2.2 匿名接口

以下接口允许未登录访问：

| 方法 | 路径 |
| --- | --- |
| `POST` | `/api/v1/auth/send-email-code` |
| `POST` | `/api/v1/auth/register` |
| `POST` | `/api/v1/auth/login` |
| `POST` | `/api/v1/auth/forgot-password` |
| `POST` | `/api/v1/auth/reset-password` |
| `GET` | `/api/v1/meta/current-period` |
| `GET` | `/api/v1/directions` |

### 2.3 统一响应

除文件下载和导出接口外，接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "timestamp": 1710000000000,
  "requestId": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

响应头也会带 `X-Request-Id`。排查问题时优先记录该值。

分页接口统一返回：

```json
{
  "list": [],
  "page": 1,
  "size": 20,
  "total": 0,
  "totalPages": 0
}
```

### 2.4 错误码

| HTTP | 业务码 | 含义 |
| --- | --- | --- |
| `400` | `40000` | 参数错误 |
| `401` | `40100` | 未登录或登录已过期 |
| `403` | `40300` | 无权限访问 |
| `403` | `40310` | 当前时期不允许该操作 |
| `404` | `40400` | 资源不存在 |
| `409` | `40900` | 数据冲突 |
| `409` | `40910` | 业务状态冲突 |
| `422` | `42200` | 数据校验失败 |
| `429` | `42900` | 请求过于频繁 |
| `500` | `50000` | 服务器内部错误 |

字段校验失败时，`data.fieldErrors` 会包含字段名和错误消息。

### 2.5 时间格式

请求体中的时间使用 ISO-8601 带时区格式，例如：

```json
"2026-07-05T23:59:59+08:00"
```

服务端会按应用时区转换并存储。

## 3. 系统配置与启动约束

### 3.1 基础设施

系统依赖：

| 依赖 | 用途 |
| --- | --- |
| MySQL | 业务数据、Flyway 迁移 |
| Redis | 验证码、发送频控、登录失败锁、JWT 黑名单 |
| SMTP | 注册验证码和重置密码验证码邮件 |
| 本地文件系统 | 任务附件、提交附件、学习资料附件 |

Redis 是认证链路强依赖。启动时会执行 Redis `PING` 校验，不可用则拒绝启动。

### 3.2 关键配置

| 配置项 | 说明 |
| --- | --- |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | 数据库连接 |
| `JWT_SECRET` | JWT 密钥，必须至少 32 字符 |
| `JWT_COOKIE_SECURE`, `JWT_COOKIE_SAME_SITE` | Cookie 安全策略 |
| `MAIL_SMTP_HOST`, `MAIL_ACCOUNT`, `MAIL_AUTH_CODE` | 邮件服务配置 |
| `AUTH_EMAIL_CODE_IP_SEND_WINDOW_SECONDS` | 验证码 IP 限流窗口，默认 3600 秒 |
| `AUTH_EMAIL_CODE_MAX_IP_SEND_COUNT` | 单 IP 窗口内验证码发送上限，默认 30 |
| `AUTH_EMAIL_CODE_GLOBAL_SEND_WINDOW_SECONDS` | 验证码全局限流窗口，默认 60 秒 |
| `AUTH_EMAIL_CODE_MAX_GLOBAL_SEND_COUNT` | 全局窗口内验证码发送上限，默认 300 |
| `AUTH_TRUST_FORWARD_HEADERS` | 是否信任代理头解析客户端 IP，默认 false |
| `AUTH_TRUSTED_PROXIES` | 可信代理 IP 或网段 |
| `APP_STORAGE_ROOT` | 文件存储根目录，默认 `./storage` |
| `APP_STORAGE_CHUNK_SIZE` | 分片大小，默认 `0B`，表示只允许直传 |
| `TASK_ATTACHMENT_MAX_SIZE` | 任务附件和提交附件上限，默认 `20MB` |
| `DEFAULT_ADMIN_ENABLED` | 是否启用默认管理员初始化，默认 true |
| `DEFAULT_ADMIN_USERNAME`, `DEFAULT_ADMIN_PASSWORD`, `DEFAULT_ADMIN_EMAIL` | 默认管理员配置 |

### 3.3 默认管理员初始化

应用启动时会检查是否存在 `ADMIN` 用户：

1. 若 `DEFAULT_ADMIN_ENABLED=false`，跳过。
2. 若数据库已有任意管理员，跳过。
3. 若启用但用户名、密码或邮箱缺失，启动失败。
4. 创建默认管理员时使用 MySQL `GET_LOCK` 防止多实例重复创建。

默认管理员会设置为：

- `role=ADMIN`
- `status=ACTIVE`
- `emailVerified=true`

## 4. 业务主流程

### 4.1 认证流程

#### 注册

1. 前端调用 `POST /api/v1/auth/send-email-code`，`scene=REGISTER`。
2. 后端要求当前处于报名期。
3. 后端执行同邮箱冷却、IP 限流、全局限流。
4. 若邮箱已注册，仍返回统一成功响应，但不发送邮件，避免邮箱枚举。
5. 若允许发送，生成 6 位验证码，写入 Redis 并发送邮件。
6. 前端调用 `POST /api/v1/auth/register`。
7. 后端校验用户名、邮箱、密码强度、验证码、报名期。
8. 注册成功后创建 `FRESHMAN` 用户并删除验证码。

#### 登录

1. 前端调用 `POST /api/v1/auth/login`。
2. 后端按 `email + clientIp` 统计登录失败。
3. 邮箱不存在、密码错误、账号禁用都返回统一登录失败消息。
4. 失败达到阈值后临时锁定。
5. 登录成功后写入登录 Cookie 和 CSRF Cookie。

#### 当前用户

`GET /api/v1/auth/me` 返回当前用户基本信息、负责分组列表 `leaderGroups` 和所在分组列表 `groups`。

#### 退出与密码

退出登录会把当前 JWT 加入 Redis 黑名单并清除 Cookie。重置密码和修改密码都会递增 `tokenVersion`，使旧 Token 失效。

### 4.2 时期流程

可配置时期：

- 报名期 `REGISTRATION`
- 选拔期 `SELECTION`
- 面试期 `INTERVIEW`

系统推导状态：

- `NOT_OPEN`
- `FINISHED`

业务限制：

| 操作 | 时期要求 |
| --- | --- |
| 注册、注册验证码、报名创建、报名修改、报名撤回 | 报名期 |
| 分组、拒绝申请、取消分组 | 选拔期 |
| 任务发布、修改、删除、提交、评测、打回 | 选拔期 |
| 公告、资料、通知、看板、导出 | 当前未绑定时期限制 |

### 4.3 方向流程

方向为两层结构：

- 一级方向：`level=1`, `parentId=null`
- 二级方向：`level=2`, `parentId=一级方向 ID`

公共方向接口只返回启用方向。管理员方向接口返回全部方向。

### 4.4 报名流程

新生可以在报名期内提交多份申请，但同一二级方向只能提交一份。申请创建后状态为 `SUBMITTED`。

申请可修改和撤回的条件：

- 当前用户是申请所有者。
- 当前处于报名期。
- 申请状态为 `SUBMITTED`。
- 申请尚未进入任何分组。

申请进入分组后状态变为 `GROUPED`。被拒绝后状态变为 `REJECTED`。撤回后状态变为 `WITHDRAWN`。

### 4.5 分组流程

管理员可以管理所有分组。负责人可以管理自己负责的分组。

负责人可以查看全局未分配申请列表，这是当前业务设计；但负责人只能将申请加入自己负责的分组。真正执行分配时，后端会校验目标分组负责人归属。

申请加入分组必须满足：

- 当前处于选拔期。
- 申请状态为 `SUBMITTED`。
- 申请尚未被分组。
- 申请方向、年级、入学年份与目标分组一致。
- 目标分组未满员。

取消分组会删除 `group_member` 关系，并把申请状态恢复为 `SUBMITTED`。拒绝申请要求备注，状态变为 `REJECTED`。

### 4.6 任务流程

任务属于具体分组，不存在全局任务。

管理员和负责人可在可管理分组中发布任务。任务必须有正文或附件，满分范围 `1..100`，截止时间必须晚于当前时间。

新生只能查看所在组任务。提交规则：

- 当前处于选拔期。
- 用户属于任务所在组。
- 当前未过截止时间。
- 提交正文和提交附件不能同时为空。
- 当前提交状态必须是 `PENDING`。

负责人或管理员可评测和打回提交。打回会清空提交正文、附件、提交时间、评测信息和分数，状态恢复为 `PENDING`。

### 4.7 公告流程

公告分为：

- `GLOBAL`：全局公告，仅管理员可发布。
- `GROUP`：组内公告，管理员可发布任意组，负责人只能发布自己负责组。

可见范围：

- 管理员可见全部公告。
- 登录用户可见全局公告、自己所在组公告、自己负责组公告。

### 4.8 学习资料流程

学习资料属于具体分组，不存在全局资料。

管理员可管理任意组资料。负责人只能管理自己负责组资料。普通用户只能查看自己所在组资料。

资料必须有正文或附件。附件必须先通过上传接口生成未绑定文件，再在创建或更新资料时绑定。

### 4.9 文件流程

上传文件先生成 `StoredFile`，初始为未绑定状态。业务对象引用附件时会校验：

- 文件由当前用户上传。
- 文件用途匹配。
- 文件尚未绑定。

上传模式由 `app.storage.chunk-size` 控制：

- `0B`：只允许直传 `/api/v1/uploads`。
- `>0`：只允许分片上传流程。

文件下载不暴露静态路径，必须经过后端鉴权接口。

### 4.10 通知流程

系统在关键业务动作后生成站内通知：

- 申请被拒绝。
- 申请被分组。
- 申请被取消分组。
- 任务发布。
- 任务打回。
- 任务评测完成。
- 公告发布。
- 学习资料发布。

通知使用 `recipientUserId + bizKey` 去重刷新。用户只能读取和标记自己的通知。

### 4.11 审计流程

系统记录认证、报名、分组、任务、公告、资料、配置、导出、文件、通知相关审计。管理员可查询审计日志。重大事件同时写入业务审计日志文件。

## 5. 接口说明

### 5.1 认证接口

#### POST `/api/v1/auth/send-email-code`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "scene": "REGISTER"
}
```

`scene` 可选 `REGISTER` 或 `RESET_PASSWORD`。

说明：

- `REGISTER` 要求当前为报名期。
- 同一邮箱和场景有发送冷却。
- 有 IP 维度和全局维度发送限流。
- 注册场景下，已注册邮箱不会被明确暴露，接口仍返回统一成功响应但不发送邮件。
- 重置密码场景下，不存在的邮箱也返回统一成功响应。

#### POST `/api/v1/auth/register`

权限：匿名。

请求体：

```json
{
  "username": "zhangsan",
  "email": "user@example.com",
  "password": "Pass1234",
  "confirmPassword": "Pass1234",
  "code": "123456"
}
```

约束：

- 用户名 3 到 32 位，只能包含字母、数字、下划线。
- 密码至少 8 位，且必须同时包含字母和数字。
- 验证码必须为 6 位数字。
- 当前必须处于报名期。

返回：`RegisterResultVo`。

#### POST `/api/v1/auth/login`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "password": "Pass1234",
  "rememberMe": false
}
```

返回：`LoginResultVo`，登录 Cookie 和 CSRF Cookie 通过 `Set-Cookie` 下发。

#### POST `/api/v1/auth/logout`

权限：已登录。

说明：清除 Cookie，并将当前 Token 加入黑名单。

#### GET `/api/v1/auth/me`

权限：已登录。

返回：`CurrentUserVo`。

#### POST `/api/v1/auth/forgot-password`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com"
}
```

说明：内部按 `RESET_PASSWORD` 场景发送验证码，响应不暴露邮箱是否存在。

#### POST `/api/v1/auth/reset-password`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "code": "123456",
  "newPassword": "NewPass123",
  "confirmPassword": "NewPass123"
}
```

说明：成功后递增 `tokenVersion`，旧登录态失效。

#### POST `/api/v1/auth/change-password`

权限：已登录。

请求体：

```json
{
  "oldPassword": "OldPass123",
  "newPassword": "NewPass123",
  "confirmPassword": "NewPass123"
}
```

说明：成功后清除当前登录态，要求重新登录。

### 5.2 公共元信息接口

#### GET `/api/v1/meta/current-period`

权限：匿名。

返回：当前时期和服务端当前时间。

#### GET `/api/v1/directions`

权限：匿名。

返回：已启用方向树。

### 5.3 报名接口

#### GET `/api/v1/applications`

权限：已登录。

返回：当前用户自己的报名申请列表。

#### GET `/api/v1/applications/summary`

权限：已登录。

返回：当前用户报名总数、待处理数、已分组数和已加入分组 ID。

#### GET `/api/v1/applications/{applicationId}`

权限：已登录，且只能访问自己的申请。

#### POST `/api/v1/applications`

权限：已登录，角色必须为 `FRESHMAN`。

请求体：

```json
{
  "realName": "张三",
  "phone": "13800138000",
  "college": "计算机学院",
  "major": "软件工程",
  "className": "软件 2401",
  "grade": "YEAR_1",
  "admissionYear": 2024,
  "directionLevel1Id": 1,
  "directionLevel2Id": 2,
  "introduction": "自我介绍"
}
```

约束：

- 手机号必须匹配 `^1\d{10}$`。
- `introduction` 最长 1000。
- 年级必须在 `app.recruitment.application.allowed-grades` 内。
- 当前必须处于报名期。

返回：`ApplicationDetailVo`。

#### PUT `/api/v1/applications/{applicationId}`

权限：已登录，申请所有者。

请求体同创建报名。仅允许修改未分组的 `SUBMITTED` 申请。

#### DELETE `/api/v1/applications/{applicationId}`

权限：已登录，申请所有者。

说明：撤回未分组的 `SUBMITTED` 申请，状态变为 `WITHDRAWN`。

### 5.4 分组查询接口

#### GET `/api/v1/groups/{groupId}`

权限：已登录，管理员、该组负责人或该组成员。

返回：`GroupDetailVo`。

#### GET `/api/v1/groups/{groupId}/members`

权限：已登录，管理员或该组负责人。

返回：`GroupMemberVo[]`。

### 5.5 管理员分组接口

#### GET `/api/v1/admin/groups`

权限：`ADMIN`。

返回：全部分组 `ManageableGroupVo[]`。

#### GET `/api/v1/admin/groups/{groupId}`

权限：`ADMIN`。

返回：`GroupDetailVo`。

#### POST `/api/v1/admin/groups`

权限：`ADMIN`。

请求体：

```json
{
  "name": "后端一组",
  "directionLevel1Id": 1,
  "directionLevel2Id": 2,
  "grade": "YEAR_1",
  "admissionYear": 2024,
  "maxSize": 10
}
```

返回：`GroupDetailVo`。

#### PUT `/api/v1/admin/groups/{groupId}`

权限：`ADMIN`。

请求体同创建分组。

说明：分组已有成员时，不允许修改方向、年级、入学年份；`maxSize` 不得小于当前人数。

#### DELETE `/api/v1/admin/groups/{groupId}`

权限：`ADMIN`。

说明：只能删除空分组。

#### PUT `/api/v1/admin/groups/{groupId}/leader`

权限：`ADMIN`。

请求体：

```json
{
  "leaderUserId": 100
}
```

说明：负责人必须是 `LEADER` 且 `ACTIVE`。

#### DELETE `/api/v1/admin/groups/{groupId}/leader`

权限：`ADMIN`。

说明：移除分组负责人。

#### GET `/api/v1/admin/groups/ungrouped-applications`

权限：`ADMIN`。

返回：全部未分组且状态为 `SUBMITTED` 的申请。

#### POST `/api/v1/admin/groups/{groupId}/applications/{applicationId}`

权限：`ADMIN`。

说明：将申请分配到目标分组。

#### POST `/api/v1/admin/groups/{groupId}/applications/{applicationId}/unassign`

权限：`ADMIN`。

请求体可选：

```json
{
  "remark": "调整分组"
}
```

说明：从目标分组移除申请，申请状态恢复为 `SUBMITTED`。

### 5.6 负责人分组接口

#### GET `/api/v1/leader/groups`

权限：`LEADER` 或 `ADMIN`。

返回：当前用户可管理的分组。管理员访问该接口时返回全部分组。

#### GET `/api/v1/leader/groups/ungrouped-applications`

权限：`LEADER` 或 `ADMIN`。

返回：全局未分组申请列表。负责人可以查看全局未分配申请，但后续只能把申请加入自己负责的分组。

#### POST `/api/v1/leader/groups/{groupId}/applications/{applicationId}`

权限：`LEADER` 或 `ADMIN`，且必须能管理该组。

## 6. 推荐联调顺序

1. 准备 MySQL、Redis、SMTP、JWT 密钥和默认管理员配置。
2. 启动服务，确认 Flyway 迁移完成。
3. 调用 `GET /api/v1/meta/current-period` 和 `GET /api/v1/directions`。
4. 管理员登录后配置时期和方向。
5. 报名期内完成新生注册、登录、报名创建和报名修改。
6. 管理员创建分组并指派负责人。
7. 选拔期内由管理员或负责人查看未分组申请并执行分组、拒绝、取消分组。
8. 上传附件，创建任务，成员提交任务，负责人评测或打回。
9. 发布公告和资料，验证可见范围。
10. 验证通知、看板、导出和审计日志。

## 7. 当前实现边界

1. 方向只支持两级结构。
2. 负责人可查看全局未分配申请，这是当前业务设计；负责人只能把申请加入自己负责的分组。
3. 文件存储为本地磁盘，不是对象存储。
4. 分片上传要求严格顺序，不支持乱序分片、秒传和断点恢复。
5. 任务打回会清空原提交内容，不保留历史版本。
6. 公告和资料列表当前未分页。
7. 导出为同步 `xlsx`，未实现异步导出任务。
8. 认证缓存当前只支持 Redis。
