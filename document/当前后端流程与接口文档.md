# FRESH 后端系统流程与接口说明

## 1. 文档说明

本文档描述当前 `backend` 仓库已经实现的后端流程与 HTTP 接口，用于前后端联调、测试验收和后续维护。本文档只覆盖后端 API、后端流程、配置和数据约定，不描述前端页面实现。

当前系统角色：

| 角色 | 枚举值 | 说明 |
| --- | --- | --- |
| 新生 | `FRESHMAN` | 注册后默认角色，可报名、查看自己分组、提交任务 |
| 负责人 | `LEADER` | 可管理自己负责的分组、任务、公告、资料、审核和导出 |
| 管理员 | `ADMIN` | 拥有管理端全局能力 |

当前关键状态枚举：

| 类型 | 枚举值 |
| --- | --- |
| 用户状态 | `ACTIVE`, `DISABLED` |
| 报名状态 | `SUBMITTED`, `GROUPED`, `REJECTED`, `WITHDRAWN` |
| 时期类型 | `REGISTRATION`, `SELECTION`, `INTERVIEW`, `NOT_OPEN`, `FINISHED` |
| 年级 | `YEAR_1`, `YEAR_2`, `YEAR_3`, `YEAR_4`, `GRADUATED` |
| 验证码场景 | `REGISTER`, `RESET_PASSWORD` |
| 任务提交状态 | `PENDING`, `SUBMITTED`, `REVIEWED` |
| 公告范围 | `GLOBAL`, `GROUP` |
| 文件用途 | `TASK_ATTACHMENT`, `TASK_SUBMISSION_ATTACHMENT`, `MATERIAL_ATTACHMENT` |
| 通知类型 | `APPLICATION_REJECTED`, `APPLICATION_GROUPED`, `APPLICATION_UNASSIGNED`, `TASK_PUBLISHED`, `TASK_RETURNED`, `TASK_REVIEWED`, `ANNOUNCEMENT_PUBLISHED`, `MATERIAL_PUBLISHED` |
| 审计模块 | `AUTH`, `APPLICATION`, `GROUP`, `TASK`, `ANNOUNCEMENT`, `MATERIAL`, `CONFIG`, `EXPORT`, `FILE`, `NOTIFICATION` |
| 审计级别 | `NORMAL`, `IMPORTANT`, `MAJOR` |

## 2. 通用约定

### 2.1 基础路径与认证方式

后端 API 统一使用 `/api/v1` 前缀。除明确标注匿名可访问的接口外，所有 `/api/**` 接口都需要登录。

登录态使用 HttpOnly Cookie：

- 登录 Cookie：`lab_recruit_token`
- CSRF Cookie：`XSRF-TOKEN`
- CSRF Header：`X-CSRF-TOKEN`

所有已登录的非安全方法请求，例如 `POST`、`PUT`、`PATCH`、`DELETE`，都需要提交 CSRF Header。Header 值应等于前端从 `XSRF-TOKEN` Cookie 读取到的值。

### 2.2 匿名接口

以下接口允许未登录访问：

| 方法 | 路径 |
| --- | --- |
| `POST` | `/api/v1/auth/send-email-code` |
| `POST` | `/api/v1/auth/register` |
| `POST` | `/api/v1/auth/login` |
| `POST` | `/api/v1/auth/forgot-password` |
| `POST` | `/api/v1/auth/reset-password` |
| `GET` | `/api/v1/meta/current-period` |
| `GET` | `/api/v1/directions` |

### 2.3 统一响应

除文件下载和导出接口外，接口统一返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "timestamp": 1710000000000,
  "requestId": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

响应头也会带 `X-Request-Id`。排查问题时优先记录该值。

分页接口统一返回：

```json
{
  "list": [],
  "page": 1,
  "size": 20,
  "total": 0,
  "totalPages": 0
}
```

### 2.4 错误码

| HTTP | 业务码 | 含义 |
| --- | --- | --- |
| `400` | `40000` | 参数错误 |
| `401` | `40100` | 未登录或登录已过期 |
| `403` | `40300` | 无权限访问 |
| `403` | `40310` | 当前时期不允许该操作 |
| `404` | `40400` | 资源不存在 |
| `405` | `40500` | 请求方法不支持 |
| `406` | `40600` | 响应类型不支持 |
| `409` | `40900` | 数据冲突 |
| `409` | `40910` | 业务状态冲突 |
| `413` | `41300` | 上传文件过大 |
| `415` | `41500` | 请求内容类型不支持 |
| `422` | `42200` | 数据校验失败 |
| `429` | `42900` | 请求过于频繁 |
| `500` | `50000` | 服务器内部错误 |

字段校验失败时，`data.fieldErrors` 会包含字段名和错误消息。

### 2.5 时间格式

请求体中的时间使用 ISO-8601 带时区格式，例如：

```json
"2026-07-05T23:59:59+08:00"
```

服务端会按应用时区转换并存储。

## 3. 系统配置与启动约束

### 3.1 基础设施

系统依赖：

| 依赖 | 用途 |
| --- | --- |
| MySQL | 业务数据、Flyway 迁移 |
| Redis | 验证码、发送频控、登录失败锁、JWT 黑名单 |
| SMTP | 注册验证码和重置密码验证码邮件 |
| 本地文件系统 | 任务附件、提交附件、学习资料附件 |

Redis 是认证链路强依赖。启动时会执行 Redis `PING` 和临时写入/删除探针校验，不可用或不可写则拒绝启动。

### 3.2 关键配置

| 配置项 | 说明 |
| --- | --- |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | 数据库连接 |
| `JWT_SECRET` | JWT 密钥，必须至少 32 字符 |
| `JWT_COOKIE_SECURE`, `JWT_COOKIE_SAME_SITE` | Cookie 安全策略 |
| `MAIL_SMTP_HOST`, `MAIL_ACCOUNT`, `MAIL_AUTH_CODE` | 邮件服务配置 |
| `AUTH_EMAIL_CODE_IP_SEND_WINDOW_SECONDS` | 验证码 IP 限流窗口，默认 3600 秒 |
| `AUTH_EMAIL_CODE_MAX_IP_SEND_COUNT` | 单 IP 窗口内验证码发送上限，默认 30 |
| `AUTH_EMAIL_CODE_GLOBAL_SEND_WINDOW_SECONDS` | 验证码全局限流窗口，默认 60 秒 |
| `AUTH_EMAIL_CODE_MAX_GLOBAL_SEND_COUNT` | 全局窗口内验证码发送上限，默认 300 |
| `AUTH_TRUST_FORWARD_HEADERS` | 是否信任代理头解析客户端 IP，默认 false |
| `AUTH_TRUSTED_PROXIES` | 可信代理 IP 或网段 |
| `APP_STORAGE_ROOT` | 文件存储根目录，默认 `./storage` |
| `APP_STORAGE_CHUNK_SIZE` | 分片大小，默认 `0B`，表示只允许直传 |
| `TASK_ATTACHMENT_MAX_SIZE` | 任务附件和提交附件上限，默认 `20MB` |
| `DEFAULT_ADMIN_ENABLED` | 是否启用默认管理员初始化，默认 true |
| `DEFAULT_ADMIN_USERNAME`, `DEFAULT_ADMIN_PASSWORD`, `DEFAULT_ADMIN_EMAIL` | 默认管理员配置 |

### 3.3 默认管理员初始化

应用启动时会检查是否存在 `ADMIN` 用户：

1. 若 `DEFAULT_ADMIN_ENABLED=false`，跳过。
2. 若数据库已有任意管理员，跳过。
3. 若启用但用户名、密码或邮箱缺失，启动失败。
4. 创建默认管理员时使用 MySQL `GET_LOCK` 防止多实例重复创建。

默认管理员会设置为：

- `role=ADMIN`
- `status=ACTIVE`
- `emailVerified=true`

## 4. 业务主流程

### 4.1 认证流程

#### 注册

1. 前端调用 `POST /api/v1/auth/send-email-code`，`scene=REGISTER`。
2. 后端要求当前处于报名期。
3. 后端执行同邮箱冷却、IP 限流、全局限流。
4. 若邮箱已注册，仍返回统一成功响应，但不发送邮件，避免邮箱枚举。
5. 若允许发送，生成 6 位验证码，写入 Redis 并发送邮件。
6. 前端调用 `POST /api/v1/auth/register`。
7. 后端校验用户名、邮箱、密码强度、验证码、报名期。
8. 注册成功后创建 `FRESHMAN` 用户并删除验证码。

#### 登录

1. 前端调用 `POST /api/v1/auth/login`。
2. 后端按 `email + clientIp` 统计登录失败。
3. 邮箱不存在、密码错误、账号禁用都返回统一登录失败消息。
4. 失败达到阈值后临时锁定。
5. 登录成功后写入登录 Cookie 和 CSRF Cookie。

#### 当前用户

`GET /api/v1/auth/me` 返回当前用户基本信息、负责分组列表 `leaderGroups` 和所在分组列表 `groups`。

#### 退出与密码

退出登录会把当前 JWT 加入 Redis 黑名单并清除 Cookie。重置密码和修改密码都会递增 `tokenVersion`，使旧 Token 失效。

### 4.2 时期流程

可配置时期：

- 报名期 `REGISTRATION`
- 选拔期 `SELECTION`
- 面试期 `INTERVIEW`

系统推导状态：

- `NOT_OPEN`
- `FINISHED`

业务限制：

| 操作 | 时期要求 |
| --- | --- |
| 注册、注册验证码、报名创建、报名修改、报名撤回 | 报名期 |
| 分组、拒绝申请、取消分组、管理员补录成员 | 选拔期 |
| 任务发布、修改、删除、提交、评测、打回 | 选拔期 |
| 公告、资料、通知、看板、导出 | 当前未绑定时期限制 |

### 4.3 方向流程

方向为两层结构：

- 一级方向：`level=1`, `parentId=null`
- 二级方向：`level=2`, `parentId=一级方向 ID`

公共方向接口只返回启用方向。管理员方向接口返回全部方向。

### 4.4 报名流程

新生可以在报名期内提交多份申请，但同一二级方向只能提交一份。申请创建后状态为 `SUBMITTED`。

申请可修改和撤回的条件：

- 当前用户是申请所有者。
- 当前处于报名期。
- 申请状态为 `SUBMITTED`。
- 申请尚未进入任何分组。

申请进入分组后状态变为 `GROUPED`。被拒绝后状态变为 `REJECTED`。撤回后状态变为 `WITHDRAWN`。

### 4.5 分组流程

管理员可以管理所有分组。负责人可以管理自己负责的分组。

负责人可以查看全局未分配申请列表，这是当前业务设计；但负责人只能将申请加入自己负责的分组。真正执行分配时，后端会校验目标分组负责人归属。负责人拒绝报名申请按共享候选池口径处理：只要申请条件匹配该负责人负责的任一分组，负责人即可在选拔期拒绝该申请；拒绝后该申请作废，其他负责人也不能再分配该申请。

申请加入分组必须满足：

- 当前处于选拔期。
- 申请状态为 `SUBMITTED`。
- 申请尚未被分组。
- 申请方向、年级、入学年份与目标分组一致。
- 目标分组未满员。

选拔期内，管理员还可以把尚未报名、已撤回或已拒绝的用户补录进分组。补录时方向、年级、入学年份取自目标分组，不重新开放报名期。同一用户同一二级方向若已 `GROUPED`，需先取消原分组。负责人不能补录。

取消分组会删除 `group_member` 关系，并把申请状态恢复为 `SUBMITTED`。拒绝申请要求备注，状态变为 `REJECTED`。

### 4.6 任务流程

任务属于具体分组，不存在全局任务。

管理员和负责人可在可管理分组中发布任务。任务必须有正文或附件，满分范围 `1..100`，截止时间必须晚于当前时间。

新生只能查看所在组任务。提交规则：

- 当前处于选拔期。
- 用户属于任务所在组。
- 当前未过截止时间。
- 提交正文和提交附件不能同时为空。
- 当前提交状态必须是 `PENDING`。

负责人或管理员可评测和打回提交。打回会清空提交正文、附件、提交时间、评测信息和分数，状态恢复为 `PENDING`。

### 4.7 公告流程

公告分为：

- `GLOBAL`：全局公告，仅管理员可发布。
- `GROUP`：组内公告，管理员可发布任意组，负责人只能发布自己负责组。

可见范围：

- 管理员可见全部公告。
- 登录用户可见全局公告、自己所在组公告、自己负责组公告。

### 4.8 学习资料流程

学习资料属于具体分组，不存在全局资料。

管理员可管理任意组资料。负责人只能管理自己负责组资料。普通用户只能查看自己所在组资料。

资料必须有正文或附件。附件必须先通过上传接口生成未绑定文件，再在创建或更新资料时绑定。

### 4.9 文件流程

上传文件先生成 `StoredFile`，初始为未绑定状态。业务对象引用附件时会校验：

- 文件由当前用户上传。
- 文件用途匹配。
- 文件尚未绑定。

上传模式由 `app.storage.chunk-size` 控制：

- `0B`：只允许直传 `/api/v1/uploads`。
- `>0`：只允许分片上传流程。

文件下载不暴露静态路径，必须经过后端鉴权接口。

### 4.10 通知流程

系统在关键业务动作后生成站内通知：

- 申请被拒绝。
- 申请被分组。
- 申请被取消分组。
- 任务发布。
- 任务打回。
- 任务评测完成。
- 公告发布。
- 学习资料发布。

通知使用 `recipientUserId + bizKey` 去重刷新。用户只能读取和标记自己的通知。

### 4.11 审计流程

系统记录认证、报名、分组、任务、公告、资料、配置、导出、文件、通知相关审计。管理员可查询审计日志。重大事件同时写入业务审计日志文件。

## 5. 接口说明

### 5.0 接口调用条件总览

本节集中列出接口的调用前置条件。后续每个接口下的“权限”和“说明”仍是具体字段、请求体和响应说明。

| 接口 | 调用身份 | 时期限制 | 资源、状态和业务限制 |
| --- | --- | --- | --- |
| `POST /api/v1/auth/send-email-code` | 匿名 | `scene=REGISTER` 时必须处于报名期；`scene=RESET_PASSWORD` 不受招新时期限制 | 同邮箱发送冷却、单 IP 限流、全局限流；注册场景下已注册邮箱仍统一返回成功但不发送验证码 |
| `POST /api/v1/auth/register` | 匿名 | 报名期 | 只能注册为 `FRESHMAN`；用户名和邮箱唯一；密码必须满足强度；必须提供有效注册验证码 |
| `POST /api/v1/auth/login` | 匿名 | 无 | 用户必须存在、状态为 `ACTIVE`、密码正确；失败次数达到阈值后临时锁定 |
| `POST /api/v1/auth/logout` | 已登录 | 无 | 当前 JWT 会加入 Redis 黑名单并清除 Cookie |
| `GET /api/v1/auth/me` | 已登录 | 无 | 登录态有效，且用户状态仍为 `ACTIVE` |
| `POST /api/v1/auth/forgot-password` | 匿名 | 无 | 内部使用 `RESET_PASSWORD` 场景验证码；受同邮箱、IP、全局发送限制 |
| `POST /api/v1/auth/reset-password` | 匿名 | 无 | 邮箱必须存在；验证码有效；新密码满足强度；成功后递增 `tokenVersion` |
| `POST /api/v1/auth/change-password` | 已登录 | 无 | 旧密码必须正确；新密码满足强度；成功后递增 `tokenVersion` 并清除当前登录态 |
| `GET /api/v1/meta/current-period` | 匿名 | 无 | 无 |
| `GET /api/v1/directions` | 匿名 | 无 | 只返回启用方向 |
| `GET /api/v1/applications`、`GET /api/v1/applications/summary` | 已登录 | 无 | 返回当前登录用户自己的报名数据；管理员和负责人也可以调用，但只会查询自己的申请 |
| `GET /api/v1/applications/{applicationId}` | 已登录 | 无 | 只能访问自己的申请；管理员和负责人不能通过该用户端接口越权查看他人申请 |
| `POST /api/v1/applications` | 已登录且角色为 `FRESHMAN` | 报名期 | 管理员和负责人无权提交报名申请；同一用户同一二级方向只能提交一份申请；方向必须启用且层级匹配；年级必须在允许范围内；创建后状态为 `SUBMITTED` |
| `PUT /api/v1/applications/{applicationId}` | 已登录且角色为 `FRESHMAN`，申请所有者 | 报名期 | 管理员和负责人无权修改报名申请；仅允许修改未分组且状态为 `SUBMITTED` 的申请；同一二级方向唯一约束仍生效 |
| `DELETE /api/v1/applications/{applicationId}` | 已登录且角色为 `FRESHMAN`，申请所有者 | 报名期 | 管理员和负责人无权通过该接口撤回报名申请；仅允许撤回未分组且状态为 `SUBMITTED` 的申请；撤回后状态为 `WITHDRAWN` |
| `GET /api/v1/groups/{groupId}` | 已登录 | 无 | 管理员、该组负责人或该组成员可访问 |
| `GET /api/v1/groups/{groupId}/members` | `ADMIN`、该组负责人 | 无 | 普通新生无权查看成员列表；负责人只能查看自己负责组成员 |
| `GET /api/v1/admin/groups/**` | `ADMIN` | 无 | 管理员查看全局分组、分组详情和全局未分组申请 |
| `POST /api/v1/admin/groups` | `ADMIN` | 无 | 分组基础配置可提前维护；方向层级必须合法；分组名称唯一；容量必须合法 |
| `PUT /api/v1/admin/groups/{groupId}` | `ADMIN` | 无 | 分组基础配置可提前维护；分组已有成员时不能修改方向、年级或入学年份；`maxSize` 不能小于当前人数 |
| `DELETE /api/v1/admin/groups/{groupId}` | `ADMIN` | 无 | 分组基础配置可提前维护；只能删除空分组 |
| `PUT /api/v1/admin/groups/{groupId}/leader` | `ADMIN` | 无 | 负责人指派可提前维护；目标用户必须是 `LEADER` 且 `ACTIVE`；如候选人是新生，需要先用管理员用户角色接口提升为负责人 |
| `DELETE /api/v1/admin/groups/{groupId}/leader` | `ADMIN` | 无 | 负责人移除可提前维护；只清空该组负责人，不自动降级用户角色 |
| `POST /api/v1/admin/groups/{groupId}/members` | `ADMIN` | 选拔期 | 管理员补录成员；按目标分组条件创建或恢复该方向申请后加入分组；不能加入管理员或禁用用户；已在该组或该方向已分组时拒绝 |
| `POST /api/v1/admin/groups/{groupId}/applications/{applicationId}` | `ADMIN` | 选拔期 | 申请必须是未分组的 `SUBMITTED`；申请方向、年级、入学年份必须匹配目标分组；目标分组未满员 |
| `POST /api/v1/admin/groups/{groupId}/applications/{applicationId}/unassign` | `ADMIN` | 选拔期 | 申请当前必须在目标分组内且状态为 `GROUPED`；取消后状态恢复为 `SUBMITTED` |
| `GET /api/v1/leader/groups` | `LEADER` 或 `ADMIN` | 无 | 负责人只返回自己负责的分组；管理员访问时返回全部分组 |
| `GET /api/v1/leader/groups/ungrouped-applications` | `LEADER` 或 `ADMIN` | 无 | 当前实现允许负责人查看全局未分组申请；真正分组时仍校验目标组归属 |

### 5.1 认证接口

#### POST `/api/v1/auth/send-email-code`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "scene": "REGISTER"
}
```

`scene` 可选 `REGISTER` 或 `RESET_PASSWORD`。

说明：

- `REGISTER` 要求当前为报名期。
- 同一邮箱和场景有发送冷却。
- 有 IP 维度和全局维度发送限流。
- 注册场景下，已注册邮箱不会被明确暴露，接口仍返回统一成功响应但不发送邮件。
- 重置密码场景下，不存在的邮箱也返回统一成功响应。

#### POST `/api/v1/auth/register`

权限：匿名。

请求体：

```json
{
  "username": "zhangsan",
  "email": "user@example.com",
  "password": "Pass1234",
  "confirmPassword": "Pass1234",
  "code": "123456"
}
```

约束：

- 用户名 3 到 32 位，只能包含字母、数字、下划线。
- 密码至少 8 位，且必须同时包含字母和数字。
- 验证码必须为 6 位数字。
- 当前必须处于报名期。

返回：`RegisterResultVo`。

#### POST `/api/v1/auth/login`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "password": "Pass1234",
  "rememberMe": false
}
```

返回：`LoginResultVo`，登录 Cookie 和 CSRF Cookie 通过 `Set-Cookie` 下发。

#### POST `/api/v1/auth/logout`

权限：已登录。

说明：清除 Cookie，并将当前 Token 加入黑名单。

#### GET `/api/v1/auth/me`

权限：已登录。

返回：`CurrentUserVo`。

#### POST `/api/v1/auth/forgot-password`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com"
}
```

说明：内部按 `RESET_PASSWORD` 场景发送验证码，响应不暴露邮箱是否存在。

#### POST `/api/v1/auth/reset-password`

权限：匿名。

请求体：

```json
{
  "email": "user@example.com",
  "code": "123456",
  "newPassword": "NewPass123",
  "confirmPassword": "NewPass123"
}
```

说明：成功后递增 `tokenVersion`，旧登录态失效。

#### POST `/api/v1/auth/change-password`

权限：已登录。

请求体：

```json
{
  "oldPassword": "OldPass123",
  "newPassword": "NewPass123",
  "confirmPassword": "NewPass123"
}
```

说明：成功后清除当前登录态，要求重新登录。

#### POST `/api/v1/applications`

权限：已登录，角色必须为 `FRESHMAN`。

调用条件：

- 当前必须处于报名期 `REGISTRATION`。
- 只有新生 `FRESHMAN` 可以提交报名申请。
- 管理员 `ADMIN` 和负责人 `LEADER` 不能通过该接口代替新生提交报名申请。
- 同一用户在同一个二级方向下只能提交一份报名申请。
- 申请方向必须是启用状态，且一级方向、二级方向层级关系必须匹配。
- 年级必须在 `app.recruitment.application.allowed-grades` 配置范围内。

请求体：

```json
{
  "realName": "张三",
  "phone": "13800138000",
  "college": "计算机学院",
  "major": "软件工程",
  "className": "软件 2401",
  "grade": "YEAR_1",
  "admissionYear": 2024,
  "directionLevel1Id": 1,
  "directionLevel2Id": 2,
  "introduction": "自我介绍"
}
```

约束：

- 手机号必须匹配 `^1\d{10}$`。
- `introduction` 最长 1000。
- 年级必须在 `app.recruitment.application.allowed-grades` 内。
- 当前必须处于报名期。

返回：`ApplicationDetailVo`。

#### PUT `/api/v1/applications/{applicationId}`

权限：已登录，角色必须为 `FRESHMAN`，且必须是申请所有者。

调用条件：

- 当前必须处于报名期 `REGISTRATION`。
- 管理员 `ADMIN` 和负责人 `LEADER` 不能通过该接口修改报名申请。
- 只能修改自己的申请。
- 仅允许修改状态为 `SUBMITTED` 的申请。
- 申请尚未进入任何分组。
- 修改后的方向仍需满足启用、层级匹配和同一二级方向唯一约束。

请求体同创建报名。

#### DELETE `/api/v1/applications/{applicationId}`

权限：已登录，角色必须为 `FRESHMAN`，且必须是申请所有者。

调用条件：

- 当前必须处于报名期 `REGISTRATION`。
- 管理员 `ADMIN` 和负责人 `LEADER` 不能通过该接口撤回报名申请。
- 只能撤回自己的申请。
- 仅允许撤回状态为 `SUBMITTED` 的申请。
- 申请尚未进入任何分组。

说明：撤回成功后状态变为 `WITHDRAWN`。

### 5.15 导出接口

导出接口返回 `xlsx` 文件，不返回统一 JSON 包装。前端调用时必须按二进制文件处理响应体，例如浏览器 `fetch` 使用 `response.blob()`，不要按 JSON 解析。

通用调用条件：

- 必须已登录。
- 只使用 `GET` 请求，不需要 CSRF Header。
- 请求必须携带登录 Cookie `lab_recruit_token`。
- 管理员路径 `/api/v1/admin/exports/**` 只允许 `ADMIN`。
- 负责人路径 `/api/v1/leader/exports/**` 允许 `LEADER` 或 `ADMIN`，但带 `groupId` 的接口必须能管理该分组。
- 当前导出不绑定招新时期限制；报名期、选拔期、面试期、未开始和已结束都可以导出。
- 数据为空时仍返回只有表头的 `xlsx` 文件，不应返回 500。
- 导出成功后会记录导出审计日志。
- 管理员路径或 `ADMIN` 通过负责人路径访问不存在的 `groupId` 时返回 `404`；普通 `LEADER` 通过负责人路径访问不存在或非自己负责的 `groupId` 时会先被权限校验拒绝并返回 `403`。
- 未登录返回 `401`，角色或分组归属不满足时返回 `403`。
- 如果底层 Redis、MySQL、磁盘或 Excel 生成依赖异常，才属于 `500` 服务器错误。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/admin/exports/applications` | `ADMIN` | 导出全部报名信息 |
| `GET` | `/api/v1/admin/exports/groups` | `ADMIN` | 导出全部分组成员 |
| `GET` | `/api/v1/admin/exports/groups/{groupId}/tasks` | `ADMIN` | 导出指定组任务结果 |
| `GET` | `/api/v1/leader/exports/groups/{groupId}/members` | `LEADER` 或 `ADMIN`，且能管理该组 | 导出组成员 |
| `GET` | `/api/v1/leader/exports/groups/{groupId}/tasks` | `LEADER` 或 `ADMIN`，且能管理该组 | 导出组任务结果 |

#### GET `/api/v1/admin/exports/applications`

调用条件：

- 当前用户必须是 `ADMIN`。
- 无时期限制。
- 不要求系统中已有报名数据；无报名时导出空表头文件。

导出内容：全部报名申请、申请人账号、方向、状态、分组信息。

#### GET `/api/v1/admin/exports/groups`

调用条件：

- 当前用户必须是 `ADMIN`。
- 无时期限制。
- 不要求系统中已有分组或成员；无成员时导出空表头文件。

导出内容：全部分组成员、账号、申请、年级、入学年份、加入时间。

#### GET `/api/v1/admin/exports/groups/{groupId}/tasks`

调用条件：

- 当前用户必须是 `ADMIN`。
- `groupId` 必须存在。
- 无时期限制。
- 不要求该组已有任务或成员；无数据时导出空表头文件。

导出内容：指定分组下每个任务对应每个成员的提交状态、提交时间、评测时间、评测人、分数和评语。

#### GET `/api/v1/leader/exports/groups/{groupId}/members`

调用条件：

- 当前用户必须是 `LEADER` 或 `ADMIN`。
- `groupId` 必须存在；`ADMIN` 访问不存在分组返回 `404`，普通 `LEADER` 访问不存在分组会因无法证明管理权限而返回 `403`。
- `LEADER` 只能导出自己负责的分组；不是该组负责人或分组不存在时返回 `403`。
- `ADMIN` 可以通过该负责人路径导出任意分组成员。
- 无时期限制。
- 不要求该组已有成员；无成员时导出空表头文件。

导出内容：指定分组成员、账号、申请、年级、入学年份、加入时间。

#### GET `/api/v1/leader/exports/groups/{groupId}/tasks`

调用条件：

- 当前用户必须是 `LEADER` 或 `ADMIN`。
- `groupId` 必须存在；`ADMIN` 访问不存在分组返回 `404`，普通 `LEADER` 访问不存在分组会因无法证明管理权限而返回 `403`。
- `LEADER` 只能导出自己负责的分组；不是该组负责人或分组不存在时返回 `403`。
- `ADMIN` 可以通过该负责人路径导出任意分组任务结果。
- 无时期限制。
- 不要求该组已有任务或成员；无数据时导出空表头文件。

导出内容：指定分组任务结果，字段同管理员指定组任务结果导出。

权限：`ADMIN`。

| --- | --- | --- |

| `role` | 无 | 按角色过滤 |

#### GET `/api/v1/admin/users/{userId}`

权限：`ADMIN`。

返回：`AdminUserDetailVo`。

#### POST `/api/v1/admin/users`

权限：`ADMIN`。

请求体：

```json
{
  "username": "freshman01",
  "email": "freshman01@example.com",
  "password": "Pass1234",
  "role": "FRESHMAN",
  "status": "ACTIVE",
  "emailVerified": true
}
```

说明：

- `username`、`email`、`password` 必填。用户名规则与注册接口一致，密码至少 8 位且必须同时包含字母和数字。
- `role` 可选，默认 `FRESHMAN`，仅允许 `FRESHMAN` 或 `LEADER`，不能创建 `ADMIN`。
- `status` 可选，默认 `ACTIVE`。
- `emailVerified` 可选，默认 `true`。管理员创建的账号会跳过邮箱验证码。
- 用户名或邮箱冲突时返回 409。

返回：`AdminUserDetailVo`。

#### PUT `/api/v1/admin/users/{userId}`

权限：`ADMIN`。

`PATCH /api/v1/admin/users/{userId}` 使用相同请求体和业务规则，用于完整修改用户信息。

请求体：

```json
{
  "username": "freshman01",
  "email": "freshman01@example.com",
  "password": "Pass1234",
  "role": "LEADER",
  "status": "ACTIVE",
  "emailVerified": true
}
```

说明：

- `username`、`email`、`role`、`status` 必填。
- `password` 可选；不传或留空时不修改密码。传入时按注册密码规则校验，并递增 `tokenVersion`，旧登录态失效。
- `emailVerified` 可选；不传时保持原值。
- 管理员不能修改自己的账号，也不能修改其他 `ADMIN` 账号。
- 角色只允许在 `FRESHMAN` 与 `LEADER` 之间调整。负责人降级为新生前，目标用户不能仍绑定任何负责的分组。
- 角色或密码变更后会递增目标用户 `tokenVersion`。

返回：`AdminUserDetailVo`。

#### DELETE `/api/v1/admin/users/{userId}`

权限：`ADMIN`。

说明：

- 管理员不能删除自己的账号，也不能删除 `ADMIN` 账号。
- 若目标用户仍绑定负责分组，或仍有报名、分组成员、任务提交/批阅、已发布任务/公告/资料、上传文件或未完成上传会话，则返回 409，不允许删除。
- 无关联业务数据的用户会被物理删除。通知收件记录随库表外键级联删除，审计日志中的操作者 ID 会被置空。
- 已有业务数据但不需要继续登录的账号，应使用状态接口停用，而不是删除。

#### PATCH `/api/v1/admin/users/{userId}/status`

权限：`ADMIN`。

请求体：

```json
{
  "status": "DISABLED"
}
```

说明：管理员不能修改自己的状态。禁用用户后，该用户旧登录态会在下次请求时失效。

#### PATCH `/api/v1/admin/users/{userId}/role`

权限：`ADMIN`。

请求体：

```json
{
  "role": "LEADER"
}
```

说明：

- 仅允许在 `FRESHMAN` 与 `LEADER` 之间调整。
- 管理员不能修改自己的角色。
- `ADMIN` 账号不能通过该接口修改角色，也不能通过该接口把普通用户提升为 `ADMIN`。
- 新生可被提升为负责人，用于后续指派为分组负责人。
- 负责人降级为新生前，目标用户不能仍绑定任何负责的分组。
- 角色变更后会递增目标用户 `tokenVersion`，旧登录态下次请求会失效，需要重新登录。

## 6. 推荐联调顺序

1. 准备 MySQL、Redis、SMTP、JWT 密钥和默认管理员配置。
2. 启动服务，确认 Flyway 迁移完成。
3. 调用 `GET /api/v1/meta/current-period` 和 `GET /api/v1/directions`。
4. 管理员登录后配置时期和方向。
5. 报名期内完成新生注册、登录、报名创建和报名修改。
6. 管理员创建分组并指派负责人。
7. 选拔期内由管理员查看全部报名申请，或由负责人查看未分组申请，并执行分组、拒绝、取消分组。
8. 上传附件，创建任务，成员提交任务，负责人评测或打回。
9. 发布公告和资料，验证可见范围。
10. 验证通知、看板、导出和审计日志。

## 7. 当前实现边界

1. 方向只支持两级结构。
2. 负责人可查看全局未分配申请，这是当前业务设计；负责人只能把申请加入自己负责的分组。
3. 文件存储为本地磁盘，不是对象存储。
4. 分片上传要求严格顺序，不支持乱序分片、秒传和断点恢复。
5. 任务打回会清空原提交内容，不保留历史版本。
6. 公告和资料列表当前未分页。
7. 导出为同步 `xlsx`，未实现异步导出任务。
8. 认证缓存当前只支持 Redis。
