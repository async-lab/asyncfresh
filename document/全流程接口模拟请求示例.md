# FRESH 全流程接口模拟请求示例

本文档只记录“如果要完整联调，从开始招新到招新结束将会发送哪些请求”。以下内容是模拟请求示例，不会真实向当前运行系统发送请求。

## 0. 统一约定

基础地址：

```text
http://localhost:8080
```

通用变量：

| 变量 | 来源 |
| --- | --- |
| `{ADMIN_AUTH_COOKIE}` | 管理员登录后响应 `Set-Cookie: lab_recruit_token=...` |
| `{ADMIN_CSRF}` | 管理员登录后响应 `Set-Cookie: XSRF-TOKEN=...` |
| `{LEADER_AUTH_COOKIE}` | 负责人登录后响应 Cookie |
| `{LEADER_CSRF}` | 负责人登录后响应 CSRF Cookie |
| `{FRESHMAN_AUTH_COOKIE}` | 新生登录后响应 Cookie |
| `{FRESHMAN_CSRF}` | 新生登录后响应 CSRF Cookie |
| `{REGISTER_CODE}` | 新生注册验证码邮件中的 6 位验证码 |
| `{DIRECTION_BACKEND_ID}` | 创建一级方向后返回的方向 ID |
| `{DIRECTION_BACKEND_JAVA_ID}` | 创建二级方向后返回的方向 ID |
| `{GROUP_ID}` | 创建分组后返回的分组 ID |
| `{LEADER_USER_ID}` | 已存在负责人用户 ID |
| `{FRESHMAN_USER_ID}` | 管理员用户列表中查询到的新生用户 ID |
| `{APPLICATION_ID}` | 新生创建报名后返回的申请 ID |
| `{TASK_ATTACHMENT_FILE_ID}` | 上传任务附件后返回的文件 ID |
| `{TASK_ID}` | 创建任务后返回的任务 ID |
| `{SUBMISSION_FILE_ID}` | 上传任务提交附件后返回的文件 ID |
| `{MATERIAL_FILE_ID}` | 上传资料附件后返回的文件 ID |
| `{MATERIAL_ID}` | 创建资料后返回的资料 ID |
| `{ANNOUNCEMENT_ID}` | 创建公告后返回的公告 ID |
| `{NOTIFICATION_ID}` | 通知列表返回的通知 ID |
| `{PERIOD_REGISTRATION_ID}` | 时期列表中报名期 ID |
| `{PERIOD_SELECTION_ID}` | 时期列表中选拔期 ID |
| `{PERIOD_INTERVIEW_ID}` | 时期列表中面试期 ID |

已登录的 `POST`、`PUT`、`PATCH`、`DELETE` 请求都需要：

```http
Cookie: lab_recruit_token={...}; XSRF-TOKEN={...}
X-CSRF-TOKEN: {...}
Content-Type: application/json
```

负责人账号说明：当前系统没有“管理员创建负责人/修改用户角色”的 HTTP 接口。负责人账号需要通过初始化数据、数据库脚本或其他运维方式预置为 `role=LEADER` 且 `status=ACTIVE`。本文示例假设 `{LEADER_USER_ID}` 和 `leader@example.com` 已存在。

## 2. 管理员登录与基础配置

### 2.1 管理员登录

```http
POST /api/v1/auth/login HTTP/1.1
Host: localhost:8080
Content-Type: application/json
Accept: application/json

{
  "email": "admin@example.com",
  "password": "AdminPass123",
  "rememberMe": false
}
```

保存响应 Cookie 为 `{ADMIN_AUTH_COOKIE}` 和 `{ADMIN_CSRF}`。

### 2.2 查询当前管理员信息

```http
GET /api/v1/auth/me HTTP/1.1
Host: localhost:8080
Cookie: lab_recruit_token={ADMIN_AUTH_COOKIE}; XSRF-TOKEN={ADMIN_CSRF}
Accept: application/json
```

### 2.3 配置完整招新时期

模拟时间线：

| 阶段 | 时间 |
| --- | --- |
| 报名期 | `2026-07-01T00:00:00+08:00` 到 `2026-07-07T23:59:59+08:00` |
| 选拔期 | `2026-07-08T00:00:00+08:00` 到 `2026-07-25T23:59:59+08:00` |
| 面试期 | `2026-07-26T00:00:00+08:00` 到 `2026-08-02T23:59:59+08:00` |

```http
POST /api/v1/admin/periods HTTP/1.1
Host: localhost:8080
Cookie: lab_recruit_token={ADMIN_AUTH_COOKIE}; XSRF-TOKEN={ADMIN_CSRF}
X-CSRF-TOKEN: {ADMIN_CSRF}
Content-Type: application/json
Accept: application/json

{
  "periods": [
    {
      "periodType": "REGISTRATION",
      "startTime": "2026-07-01T00:00:00+08:00",
      "endTime": "2026-07-07T23:59:59+08:00",
      "enabled": true
    },
    {
      "periodType": "SELECTION",
      "startTime": "2026-07-08T00:00:00+08:00",
      "endTime": "2026-07-25T23:59:59+08:00",
      "enabled": true
    },
    {
      "periodType": "INTERVIEW",
      "startTime": "2026-07-26T00:00:00+08:00",
      "endTime": "2026-08-02T23:59:59+08:00",
      "enabled": true
    }
  ]
}
```

## 10. 招新结束：关闭时期并验证

本阶段假设系统时间已经晚于所有启用时期的 `endTime`，例如 `2026-08-03T00:00:00+08:00` 之后。此时 `GET /api/v1/meta/current-period` 应返回 `FINISHED`。

如果需要主动关闭所有时期，可由管理员把时期配置更新为 `enabled=false`。关闭后当前时期通常为 `NOT_OPEN`；如果保留启用且结束时间已过，则当前时期为 `FINISHED`。

Accept: application/json

{
  "periods": [
    {
      "periodType": "REGISTRATION",

    },
    {
      "periodType": "SELECTION",
